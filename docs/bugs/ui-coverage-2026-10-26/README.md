## Revue indépendante du correctif header safe areas

Le patch `proposed-header-only.patch` a été relu : seule la classe de `TopBar` change. Génération indépendante avec le `presetUno` installé confirmée : `calc(56px + env(...))` est émis avec les espaces CSS requis, les paddings `max(...)` sont générés et le breakpoint `sm` vaut640px. Sans inset, l’espacement reste celui de `px-4`/`sm:px-6` :14/21px avec racine14px (et12/18px avec racine12px), pas16/24px supposés. Avec inset supérieur44px, hauteur attendue100px et padding44px conservent la zone de contrôles de56px, sous réserve du box-sizing calculé du build. Les côtés utilisent le maximum entre marge existante et inset, sans doubler les deux.

`sticky top-0`, le z-index et les ancêtres sont inchangés ; aucun nouveau conteneur de défilement ni positionnement fixe n’est introduit. La hauteur supplémentaire reste dans le flux. Aucun blocage statique identifié ; cette génération CSS isolée ne remplace pas une recette compilée. À vérifier sur le prochain build : box-sizing/hauteur effective, contrôles44px entièrement dans les bornes portrait/paysage, état sans inset à320/640/820/1440, sticky après scroll, ouverture/fermeture des menus et focus, absence de débordement et saisie conservée au resize. Les descendants et le contenu de page ne sont pas rendus automatiquement compatibles safe areas par ce seul header.

L’absence de navigation basse dans AppShell est préexistante ; celle de BaseChat relève d’un autre contexte. Le correctif header ne supprime aucune navigation, mais **ne satisfait pas la demande globale de menu bas mobile/tablette**, qui reste ouverte explicitement.
