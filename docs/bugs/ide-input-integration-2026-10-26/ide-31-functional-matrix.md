# Matrice fonctionnelle des 31 entrées IDE — preuves locales disponibles

**Aucun des 31 panneaux n’est déclaré intégralement opérationnel en production par cette matrice.** Elle consolide les reçus existants ; aucune nouvelle recette, stack ou modification de dépôt n’a été effectuée pour sa préparation. Le registre audité contient 31 clés adressables, dont `domains`, alias du parcours Deploy. Share et Commands sont des actions, pas deux panneaux supplémentaires.

**Statuts :** « Fonctionne mesuré » couvre seulement le comportement précisé ; « Non testé » signifie absence de validation de la fonction métier ; « Bloqué » désigne une dépendance effectivement absente dans l’environnement local ; « Défaut reproduit » apparaît dans le tableau des anomalies, avec sa correction et son état de livraison. Un état vide affiché correctement ne valide pas les opérations qui rempliraient cet état.

## Diagnostic #802 : ne pas transformer une hypothèse CI en défaut produit établi

Le test « explicit provisional README stays in project A after switching to B at 390 » a été récupéré depuis la tête CI `279440d2…` : source identique au local après normalisation du newline final. Sur le build local `6f270b9…`, il passe, ainsi que le contrôle archive retenue à 390 et une sonde avec réponses réelles loader/archive/ide-state retardées. Le build n’est pas exactement la tête CI ; les différences focus/composition sont qualifiées, les sources workbench/files/ProjectWorkspaceProvider ont été comparées par le parent.

La sonde n’observe aucun titre visible A avec contenu B, ni contenu B après `configureProject(A)`. Les sélections serveur locales sont A=README.md et B=project-b.txt. Un contretest borné fait expirer l’assertion originale après 5 023 ms pendant que le loader A est réellement retenu : URL=A mais router=B, navigation=loading, titre et document B. Après libération, A revient intact. **Ce symptôme est reproduit sous latence contrôlée ; la cause du CI original n’est pas prouvée.** Aucun patch produit ni hausse de timeout du dépôt n’a été effectué dans ce diagnostic.

## Limites communes et provenance

- La matrice de surfaces repose principalement sur le build `6f124189…` : 320/390/820/1440, Chromium, thème clair. Les 21 entrées complémentaires et les 9 initiales ne sont pas 30 validations complètes de métier. Certains premiers relevés ont capturé un shell transitoire ; les états retenus et leurs limites sont explicités dans les reçus.
- Le zoom des compléments est le zoom natif Chromium confirmé par CDP, pas un `zoom` CSS. Aucune validation Safari matériel, thème sombre complet ou production authentifiée.
- Fixtures synthétiques ; API locale et base locales réelles pour setup/lectures/persistance. Importer via API pour préparer une fixture ne valide pas le parcours Import de l’interface. Les mutations navigateur étaient bloquées pendant les matrices de lecture, à l’exception des tests de persistance qui autorisaient leur état IDE isolé.
- Les erreurs 403/503 sont injectées explicitement pour la reprise UI ; elles ne prouvent pas les politiques d’autorisation réelles. Des 429 dus à la cadence de fixtures ont été conservés, puis les seuls cas concernés repris avec configuration de l’API éphémère ajustée ; aucun seuil produit modifié.
- Aucun provider, déploiement de projet client, DNS, credential réel, installation payante, scanner, workflow ou restauration réelle activé dans ces recettes. Stacks de ces lots nettoyées. Traces privées susceptibles de contenir des sessions synthétiques : ne pas publier leurs fichiers bruts sans traitement.
