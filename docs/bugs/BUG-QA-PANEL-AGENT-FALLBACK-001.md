## Bug

**Un `?panel=` non reconnu est avalé en silence : sur mobile il rend le panneau Déploiements, sur desktop il laisse l'onglet précédent — dans les deux cas l'URL ment sur ce qui est affiché.** Deux défauts se combinent. **(1) Allow-list trop étroite** : `readPanelSearchParam(searchParams, IDE_URL_PANELS)` rejette toute clé absente de `IDE_URL_PANELS` et renvoie `undefined` — sans avertir, sans corriger l'URL. Or **`agent` n'est PAS dans `IDE_URL_PANELS`** alors qu'il est l'un des **3 onglets mobiles par défaut** (`ECODE_MOBILE_DEFAULT_TABS = ['preview','agent','deployments']`). **(2) Repli muet sur `deployments`** : `activeMobileServicePanel` fait `isIdeManagementPanel(activeProjectPanel) ? activeProjectPanel : 'deployments'`. Résultat : **25 des 50 clés** de `ECODE_MOBILE_TAB_META` ne sont pas des management panels et retombent donc toutes sur Déploiements — `preview, agent, deploy, files, editor, search, locks, actions, assistant, publishing, app-storage, auth, console, debug, developer, history, multiplayer, collaboration, collaborate, checkpoints, shell, kv-store, storage, web, tools`. **(3) Titre et contenu décorrélés** : le panneau reçoit `panel={activeMobileServicePanel}` (issu de l'URL) mais `displayTitle={mobileServiceHeaderTab?.name}` (issu de `activeMobileOpenTabId`) — l'en-tête peut donc afficher « Agent » au-dessus du contenu Déploiements, ce qui est exactement le symptôme observé. ⚠️ **Le tap sur l'onglet n'est PAS affecté** : `activateMobileTool('agent')` fait `setProjectPanelSearchParam()` (efface le param) et bascule sur `chat`. Le défaut ne se déclenche que par **URL directe** (deep-link, lien partagé, rechargement, restauration d'onglet).
